# Publication exclusion register

The following material must not be included in a public release merely because
it exists in the working tree.

| Material | Decision | Reason | Public replacement |
|---|---|---|---|
| `data/gsMap_resource/` | Exclude | Large third-party resource | Cite the gsMap source, version, retrieval date, and checksum |
| Local GWAS and spatial inputs under `data/` | Exclude pending source-by-source review | Large; some sources may restrict redistribution | Accession/DOI manifest plus deterministic preparation commands |
| Full `results/` tree | Exclude | Multi-gigabyte intermediates, smoke runs, superseded outputs, scheduler artifacts, and duplicates | Curated frozen CSV/JSON files consumed by final plots and tables |
| Full `scripts/` tree | Exclude | Contains exploratory/deprecated variants and programs bound to `/scratch/user/...`, `/home/...`, or `/Users/...` | Maintained parameterized analysis and visualization entry points admitted individually |
| `scripts/_deprecated/` | Exclude | Explicitly superseded | None unless a final artifact still depends on it, which is a release blocker |
| `scripts/slurm/` and `submit_*.sh` | Exclude by default | Site-specific orchestration is not a portable analysis entry point | Optional scheduler examples generated from portable commands |
| `paper/*.aux`, `*.log`, `*.fls`, `*.fdb_latexmk`, `*.blg`, `*.out` | Exclude | Build products | Rebuild from manuscript source |
| `paper/.overleaf-*` | Exclude | Personal/editor synchronization state | None |
| Reporting forms and local correspondence | Exclude from software release | Submission administration, not computational reproduction | Upload through the journal only |
| Legacy Supplementary Tables 1--24 | Exclude | Their 69 retained sheets have been consolidated into nine final workbooks; publishing both sets creates redundant and potentially divergent copies | Publish only final Supplementary Tables 1--9 plus the `Legacy Mapping` sheet |
| `quickstart/output/demo_gwas.tsv` and `demo_visium.h5ad` | Exclude | Generated, large smoke-test inputs | Generate deterministically with `run_quickstart.py` |
| Untracked experimental modules (`genetic_response.py`, `response.py`, `simulation.py`) and their tests | Exclude pending independent scientific review | Not part of the tagged package or manuscript implementation | Admit only after API, statistical, provenance, and regression review |

## Findings from the working-tree audit

- Many analysis programs contain personal absolute paths and cannot run from a
  clean clone. This is a portability defect, not by itself a credential leak.
- The final composite figure files exist under `paper/figures/`, but no complete
  set of final visualization entry points was identified by output name. The
  paper cannot truthfully claim that every figure is regenerated by the public
  repository until this gap is closed.
- Several analysis families have multiple similarly named versions and
  `superseded`, `smoke`, `dryrun`, or dated outputs. Publishing them without a
  frozen manifest would make it ambiguous which result supports the paper.
- The quickstart uses external gsMap resources and normally exercises aggregate
  S-LDSC only. It is not a substitute for the empirical per-pair calibration.
- The final nine-workbook SI package has 77 sheets and complete sheet-level
  manifest coverage, but no tracked clean-clone builder currently regenerates
  the consolidated filenames and layout. Legacy builders are provenance only.
- The frozen observed and null directories required to regenerate
  Supplementary Table 7 are absent from the current local result tree, although
  the final workbook exists. Do not release that workbook as independently
  reproducible until those inputs are restored and checksummed.
- No password, access token, or API key was identified by the static patterns
  used in this audit. A dedicated secret scanner remains a required release
  check because pattern matching is not proof of absence.
